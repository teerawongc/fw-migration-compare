ภาพรวม

เครื่องมือนี้เปรียบเทียบ Policy / NAT / Network Objects / Service Objects ระหว่าง Check Point (ต้นทาง) กับ Cisco FMC (ปลายทาง) เพื่อหาว่ามีอะไร Match, Missing, Mismatch หรือ Extra บ้าง ก่อน/หลัง migrate

① Export จาก Check Point (ฝั่งซ้าย)

เข้า SmartConsole แล้ว export แต่ละไฟล์ตาม tab ด้านบน:

  • Security_Policy.xml — File → Export Policy
  • NAT_Policy.xml — NAT → Export
  • network_objects.xml — Manage Objects → Export
  • services.xml — Manage Services → Export

คลิกที่กล่องแต่ละอันในแถบซ้าย (หรือลากไฟล์มาวาง) เพื่ออัปโหลด

② Export จาก Cisco FMC (ฝั่งขวา)

ดึงผ่าน FMC REST API — ทุก endpoint ต้องใส่ ?expanded=true เสมอ แล้วนำไฟล์ JSON ที่ได้มาลากวาง หรือกด "เลือกไฟล์" (อัปโหลดได้หลายไฟล์พร้อมกัน ระบบจะ merge ให้อัตโนมัติ) หรือ paste JSON ลงกล่องข้อความก็ได้

Security Policy (แบ่งหน้าละ 1000 รายการ):

GET /policy/accesspolicies/{id}/accessrules?expanded=true&limit=1000&offset=0
GET /policy/accesspolicies/{id}/accessrules?expanded=true&limit=1000&offset=1000
GET /policy/accesspolicies/{id}/accessrules?expanded=true&limit=1000&offset=2000 ...

NAT Policy:

GET /policy/ftdnatpolicies/{id}/manualnatrules?expanded=true&limit=1000
GET /policy/ftdnatpolicies/{id}/autonatrules?expanded=true&limit=1000

Network Objects:

GET /object/hosts?expanded=true&limit=1000&offset=0  (วนจน offset ครบ)
GET /object/networks?expanded=true&limit=1000
GET /object/ranges?expanded=true&limit=1000
GET /object/networkgroups?expanded=true&limit=1000

Service Objects:

GET /object/protocolportobjects?expanded=true&limit=1000&offset=0
GET /object/icmpv4objects?expanded=true&limit=1000
GET /object/portobjectgroups?expanded=true&limit=1000
⚠ FMC 7.x ใช้ endpoint /object/protocolportobjects เดียว (รวม TCP+UDP ในตัวเดียวกัน แยกด้วย field protocol) — endpoint แยก /object/tcpportobjects และ /object/udpportobjects ไม่มีจริงบน FMC 7.6.5 (ทดสอบแล้วได้ 404) ห้ามใช้

③ เปรียบเทียบ

  • เลือก tab (Security Policy / NAT Policy / Network Objects / Service Objects) ที่มุมบน — CP file และ FMC data จะสลับตาม tab ที่เลือก
  • ปุ่ม CP → FMC ⇄ ที่ header สลับทิศทางเปรียบเทียบ (ปกติเช็คว่า CP มีอะไรที่ FMC ยังไม่มี — กดสลับเพื่อเช็คกลับด้าน)
  • ปรับ checkbox ตัวเลือกด้านซ้ายได้ตามต้องการ (เช่น รวม Disabled rules, เทียบชื่อ Object ตรงๆ)
  • กด ▶ เปรียบเทียบ เมื่ออัปโหลดครบทั้งสองฝั่ง

④ อ่านผลลัพธ์

แท็บผลลัพธ์แบ่งเป็น ✓ Match ✗ Missing ⚠ Mismatch + Extra — คลิกแถวเพื่อดูรายละเอียดเทียบข้าง CP/FMC ใช้ช่องค้นหาเพื่อกรองได้

Security Policy มีอีก 2 แท็บ (v3.7.0):
⧉ Rule ที่ถูกแยก — FMT มีเพดาน object ต่อ 1 access rule (~50) CP rule ที่ object เกินจะถูกหั่นเป็น Rule_#99-1 / -2 / -3 เครื่องมือจะรวมกลับเป็น rule เดียวแล้ว union object ทั้งหมดก่อนเทียบ จึงไม่ขึ้น Mismatch/Extra ปลอมอีก (ปิดได้ที่ตัวเลือก “รวม rule ที่ FMT แยก”)
⇅ ลำดับผิด — FMT ไม่ได้ย้าย rule ตามลำดับเดิมเสมอ (เช่น CP #3200 ไปโผล่ตำแหน่ง 250) การเทียบเนื้อหาใช้เลข Rule เป็นตัวจับคู่ (ไม่ใช้ตำแหน่ง) ส่วนลำดับตรวจแยกด้วย LIS จึง flag เฉพาะ rule ที่ต้องย้ายจริง ไม่ลามทั้งแถว — ลำดับสำคัญ เพราะ rule บนชนะเสมอ การสลับที่ทำให้เกิด shadow หรือ traffic หลุดได้

⑤ Export ผลลัพธ์

  • ⬇ CSV — export ผลเปรียบเทียบทั้งหมดเป็นไฟล์ตาราง
  • 📋 Bulk JSON — export เฉพาะรายการ Missing เพื่อสร้างเข้า FMC ผ่าน bulk API (แยกไฟล์ตาม type อัตโนมัติ: hosts / networks / ranges / groups)
⚠ FMC bulk endpoint ไม่รับ JSON array มาตรฐาน ต้อง POST เป็น object ต่อกันตรงๆ โดยไม่มี comma หรือ [ ] คั่น — ไฟล์ที่ export จากเครื่องมือนี้ทำรูปแบบให้ถูกต้องแล้ว ใช้วางใน body ของ POST ได้เลย เช่น POST /object/hosts?bulk=true สำหรับ hosts, /object/networks?bulk=true สำหรับ networks, /object/protocolportobjects?bulk=true สำหรับ TCP/UDP services (type: ProtocolPortObject + field protocol: TCP หรือ UDP)

Group ต้องแปลง member เป็น object ID ของ FMC เองก่อน POST เพราะ NetworkGroup ต้องอ้างอิง ID ของสมาชิกที่มีอยู่แล้วในระบบ
